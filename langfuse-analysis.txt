LANGFUZE CODEBASE ANALYSIS FOR CLAUDE.md

## 1. Project Structure & Architecture

### Overall Architecture
- **Version**: 2.65.1 (production-ready v2, v3 in development)
- **Type**: Next.js 14 monorepo for LLM observability platform
- **Database**: PostgreSQL with Prisma ORM
- **State**: v2 production, v3 worker under development

### Current v2 Architecture
- Web service: Next.js 14 with App Router + tRPC API
- Client SDKs: Python and JavaScript
- Database: PostgreSQL + Redis for caching
- Public ingestion API for SDK data
- React UI with shadcn/ui components

### Emerging v3 Architecture
- Worker service: Express.js with BullMQ for async processing
- ClickHouse for analytics (planned)
- Separation of web and worker services

## 2. Monorepo Structure

```
langfuse/
├── web/                    # Main Next.js application (API + UI)
├── worker/                 # Background processing service (experimental)
├── packages/
│   ├── shared/             # Shared utilities, DB models, auth
│   ├── config-eslint/      # ESLint configurations
│   └── config-typescript/  # TypeScript configurations
├── ee/                    # Enterprise edition features
└── scripts/               # Build and development scripts
```

### Key Packages

**web/** - Main application
- Next.js 14 with App Router
- tRPC API endpoints
- React UI with shadcn/ui components
- Public ingestion API
- NextAuth.js authentication

**worker/** - Background processing (experimental)
- Express.js server
- BullMQ for task queue
- Not recommended for production in v2.x

**packages/shared/** - Shared functionality
- Prisma schema and database models
- Authentication utilities
- Email services
- Storage services (S3)
- Common types and utilities

## 3. Development Setup & Commands

### Prerequisites
- Node.js 20
- pnpm v9.5.0
- Docker (for database)

### Quick Start
```bash
# Setup development environment
pnpm run infra:dev:up      # Start database
cp .env.dev.example .env   # Create env file
pnpm install               # Install dependencies
pnpm --filter=shared run db:migrate  # Run migrations
pnpm --filter=shared run db:seed:examples  # Seed data
pnpm run dev               # Start development server
```

### Key Development Commands
```bash
pnpm run dx                # Full dev setup (deps, DB reset, seed, start)
pnpm run dx-f              # Force reset setup
pnpm run nuke              # Clean build artifacts
pnpm run build             # Build all packages
pnpm run test              # Run tests
pnpm run test:e2e          # Run E2E tests
pnpm run lint              # Lint code
```

## 4. Database Architecture

### Core Technologies
- **PostgreSQL**: Primary database
- **Prisma ORM**: Database access and migrations
- **Kysely**: Type-safe SQL queries
- **Redis**: Caching and sessions

### Key Data Models
- **Users & Auth**: NextAuth.js integration
- **Projects**: Multi-tenant organization
- **Traces**: Top-level execution tracking
- **Observations**: Spans, generations, events
- **Scores**: Evaluations and feedback
- **Prompts**: Managed prompt templates
- **Datasets**: Testing datasets

### Database Management
- Migrations via Prisma
- Schema in `packages/shared/prisma/schema.prisma`
- Reset with `pnpm --filter=shared run db:reset`

## 5. API Structure

### Authentication & Authorization
- **NextAuth.js** for authentication
- **Project-based access control**
- **Procedure types**:
  - `publicProcedure`: No auth required
  - `protectedProcedure`: User must be logged in
  - `protectedProjectProcedure`: User must be project member

### Key APIs
**Public Ingestion API** (`/public/api/ingestion`):
- Handles trace data from SDKs
- Validates and stores observations
- Processes tokens and model matching

**Internal APIs** (tRPC):
- Project management
- User authentication
- Dashboard data
- Prompt management
- Dataset operations

### API Versioning
- v2: Current production (single database)
- v3: Planned (worker separation + ClickHouse)

## 9. Key Architecture Patterns

### Service Interaction
1. Client SDKs → Public Ingestion API → PostgreSQL
2. Web UI → tRPC API → PostgreSQL
3. Worker Service (v3) → Redis Queue → PostgreSQL + ClickHouse

### Data Flow
- Traces: Top-level execution units
- Observations: Spans, generations, events
- Scores: Evaluations and feedback
- Public/Private: Project-based access

### Multi-tenancy
- Project-based isolation
- User project memberships
- Project-level access control
- Admin users with global access
